SECTION 1: HIGH-LEVEL ARCHITECTURE & API INVOCATION MECHANISM
====================================================================================================

[1.1 THE FETCH-AND-CACHE ARCHITECTURE]
- Problem: Calling an external news API on every web page reload introduces high latency (>1 sec),
  wastes network bandwidth, and quickly hits NewsAPI daily quota limits.
- Solution: Fetch-and-Cache design.
  1. The user manually triggers news fetching by clicking "Fetch News" or via REST API.
  2. The backend sends an HTTP request to NewsAPI.org.
  3. Received articles are processed, sanitized, and stored locally in SQLite (`NewsArticle` model).
  4. Subsequent dashboard loads query local SQLite directly (<10ms).
- Multi-Tenancy: Every article record contains `business_id` to guarantee complete data isolation 
  between different enterprise accounts.

[1.2 WHEN, WHERE & HOW NewsAPI IS CALLED IN DETAIL]

* WHEN IS IT CALLED?
  - Trigger 1 (Web Interface): When user submits form in `news.html` -> POST `/nuha/news/fetch`.
  - Trigger 2 (REST API Client): When an HTTP client sends POST request to `/nuha/news/api/fetch`.

* WHERE IS IT CALLED?
  - File     : `marketmind/routes/nuha/news.py`
  - Function : `fetch_and_save_news(query, business_id, competitor_id, page_size)`
  - Exact Line: Line 34 (`response = requests.get(NEWS_API_URL, params=params, timeout=10)`)

* HOW IS IT CALLED (STEP-BY-STEP)?
  1. Endpoint URL : `https://newsapi.org/v2/everything`
  2. HTTP Method  : GET
  3. Query Parameters (`params` dictionary):
     - `q`         : Search terms. For Industry News = `f"{niche} {industry}"`. For Competitor = `competitor.name`.
     - `language`  : `'en'` (Restricts search to English news).
     - `sortBy`    : `'publishedAt'` (Orders results newest first).
     - `pageSize`  : `12` (Limits returned items to 12 articles).
     - `apiKey`    : Reads authentication key from environment variable `NEWS_API_KEY`.
  4. Timeout      : `timeout=10` (Prevents backend server hanging if NewsAPI drops connection).
  5. JSON Parsing : `data = response.json()` parses HTTP body into Python dictionary.
  6. Overwrite    : Deletes existing articles for that category before saving new ones (`.delete()`).
  7. Parsing Date : Replaces ISO 'Z' with '+00:00' and converts to `datetime` object.
  8. DB Storage   : Creates `NewsArticle` objects, adds to `db.session`, and runs `db.session.commit()`.

SECTION 7: TOP VIVA DEFENSE QUESTIONS & PERFECT ANSWERS
====================================================================================================

Q1: Why did you implement a cached database model (`NewsArticle`) instead of making live NewsAPI calls on every page load?
A1: Three main reasons:
    1. Performance: Querying local SQLite database takes <10ms, whereas external API requests take 500ms–2000ms.
    2. API Limits & Cost: Free tier API keys have strict daily request quotas. Caching minimizes API usage.
    3. Reliability: Users can view cached news even if NewsAPI is offline or rate-limited.

Q2: Where and how is the external NewsAPI called in `news.py`?
A2: In `routes/nuha/news.py`, inside the `fetch_and_save_news()` function at Line 34 using `requests.get()`. 
    It passes params: `q` (query), `language='en'`, `sortBy='publishedAt'`, `pageSize=12`, and `apiKey`.

Q3: How do you differentiate Industry News from Competitor News in the database?
A3: Using the `competitor_id` Foreign Key in the `NewsArticle` table.
    - If `competitor_id IS NULL`: It is Industry News (queried using business niche & industry keywords).
    - If `competitor_id IS NOT NULL`: It is Competitor News (queried using that competitor's name).

Q4: What happens during cache invalidation when a user clicks "Fetch News"?
A4: Lines 41-44 in `news.py` execute `NewsArticle.query.filter_by(...).delete()`. 
    This deletes old cached records for that specific category before saving newly fetched articles, 
    preventing duplicate accumulation in SQLite.

Q5: Why are `news.html` and `_news_card.html` split into separate files?
A5: To adhere to the DRY (Don't Repeat Yourself) principle. Both Industry News and Competitor News 
    tabs render article cards in a grid. Writing the card HTML once in `_news_card.html` allows us to 
    reusably embed it using `{% include 'nuha/_news_card.html' %}` inside both tab loops.
